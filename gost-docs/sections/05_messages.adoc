== Сообщения

При возникновении ошибок валидации, авторизации или внутренних сбоев сервис возвращает стандартный HTTP-код состояния и JSON-объект вида `{"error": "<описание ошибки>"}`.

=== Перечень диагностических сообщений и действия при сбоях

[cols="1,2,3,3", options="header"]
|===

| Код HTTP | Текст сообщения (`error`) | Причина возникновения | Действия программиста

| `400`
| `Invalid request: missing 'q' parameter`
| В теле JSON-запроса отсутствует обязательный параметр или передан пустой текст.
| Проверить наличие и непустое значение обязательных полей (`q`, `source`, `target`) перед отправкой запроса.

| `400`
| `'<lang>' is not supported`
| Указан код языка, модель которого не загружена на сервере.
| Запросить актуальный список доступных языков через метод `GET /languages` и скорректировать параметры.

| `403`
| `Invalid API key`
| Отсутствует или указан недействительный ключ доступа `api_key`.
| Проверить корректность значения `api_key` в конфигурации клиентского приложения или получить новый ключ у администратора.

| `429`
| `Slowdown: Rate limit exceeded`
| Превышено допустимое количество запросов в минуту с одного IP-адреса или ключа.
| Реализовать в клиентском коде задержку перед повторной отправкой запроса (механизм *Exponential Backoff*).

| `500`
| `Cannot translate text`
| Внутренняя ошибка нейросетевого движка при обработке нестандартных символов или сбой воркера.
| Проверить корректность кодировки UTF-8 во входной строке; при повторении ошибки обратиться к системному программисту для анализа логов контейнера.
|===
